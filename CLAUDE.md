# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Nomad Life is a Flask + SQLite web app that tracks the days a digital nomad spends in each country per solar year and stores receipts. No build step, no JS bundler, no linter configured.

## Commands

```bash
./runWebApp.sh                      # create config.env and .venv if missing, install requirements when
                                    # requirements.txt changes, free APP_PORT, start the app
.venv/bin/python -m unittest        # full test suite (tests/)
.venv/bin/python -m unittest tests.test_package.PackageContentsTests.test_structure_and_order   # one test
.venv/bin/python -W ignore::ResourceWarning -m unittest   # quieter output
FLASK_DEBUG=1 .venv/bin/python app.py                     # debug mode (templates reload)
.venv/bin/python scripts/build_map.py                     # regenerate static/img/world.svg and countries_geo.py (downloads Natural Earth)
.venv/bin/python scripts/backup.py --dest DIR --keep 14   # one tar.gz with nomad.db and .secret_key (paths from config.env);
                                                          # --with-receipts adds uploads/, which is otherwise backed up off-site as it is
.venv/bin/flask --app app zip-receipts                    # convert pre 1.2.12 plain receipt files to ZIP
.venv/bin/flask --app app reset-2fa <email>               # remove an account's two-factor secret
.venv/bin/pip-audit -r requirements.txt                   # what CI runs (pip install pip-audit first)
```

- Tests: a feature gets its own file (`tests/test_<feature>.py`); the fixes of a release go in `tests/test_fixes_<version without dots>.py` (for example `test_fixes_1212.py`), security fixes in `test_security_<version>.py`.
- Production deployment (gunicorn, nginx, systemd, backups, upgrades) is documented in `setup_vps.md`; server monitoring (Beszel, reached through an SSH tunnel) in `beszel.md`.

- Without `FLASK_DEBUG=1`, Jinja templates are cached: restart the server after editing templates.
- Static CSS/JS are cached for 7 days and linked with `?v=<asset_version>`, a hash of `style.css` and `theme.js` computed at startup, so edits reach browsers after a server restart without a version bump.
- `config.env` wins over exported shell variables for every key it contains (`load_dotenv(..., override=True)`); `runWebApp.sh` also reads `APP_PORT` with the same parser and exports it. To point a manual server at a scratch database, pass overrides to `create_app({...})` instead of environment variables.

## Architecture

**Single Flask module.** `app.py` holds config, helpers and all routes (`register_routes`). It ends with `app = create_app()`, so importing `app` loads `config.env` and initializes `data/nomad.db`. Tests call `create_app({...})` with overrides; `tests/helpers.py` (`AppTestCase`) gives each test a temporary database and upload folder with CSRF disabled, blanks the Gmail settings (`config.env` may hold real ones), records emails in `self.outbox` instead of sending, and its `signup()` goes through the confirmation link and signs in (new accounts are on Free: call `self.set_plan("pro")` before testing the accountant package; `age_emails()` skips the one minute email cooldown).

**Database** (`db.py`). One sqlite connection per request on `g`. `query()` reads, `execute()` commits (and rolls back on error), `transaction()` runs `BEGIN IMMEDIATE` for check-then-write sequences: a limit or one time check (movement and ticket caps, reset and email change links, "only if still open") must be repeated inside it, or be a condition of the UPDATE with its rowcount checked. Never do slow work (file rewrites, hashing, email) while holding it. `try_execute()` is for housekeeping that may be skipped when the database is busy (the session last seen stamp, the minute purge), so a page view never fails behind another writer. Schema is `CREATE TABLE IF NOT EXISTS` in `SCHEMA`; there is no migration framework. New columns go in `SCHEMA` and in `db.MIGRATIONS` (add column, backfill), which `migrate()` applies on every start, idempotently and under `BEGIN IMMEDIATE`. Nothing in `SCHEMA` may reference a migrated column, because old databases run `SCHEMA` before the column exists. Foreign keys cascade (years -> movements -> documents), enabled per connection.

**Ownership.** Every private query is scoped by `user_id`. Use `get_year_or_404`, `get_movement_or_404`, `get_document_or_404`: other users' data must return 404, never 403.

**Auth.** Flask-Login with `User.get_id()` = `"<id>:<password fingerprint>"`, so a password reset invalidates every other session and remember cookie. Reset tokens (itsdangerous) carry the same fingerprint. Cookie names are app specific (`nomadlife_session`, `nomadlife_remember`), `SameSite=Lax`, and `Secure` when `APP_BASE_URL` is `https://`. All POST forms carry the Flask-WTF CSRF token; tokens live as long as the session (`WTF_CSRF_TIME_LIMIT=None`), and a stale token on sign out still signs out. Redirects after sign in go through `safe_next()` (same site paths only, no control characters), and the unauthorized handler only puts GET pages in `next`. `<int:...>` URL parts are capped to SQLite's range (`DbIntConverter`), so huge ids are a 404.

**Email confirmation.** Sign up creates the user with `verified_at` NULL and emails a `/verify/<token>` link; it does not sign in. Confirming sets `verified_at` and sends the user to sign in (no auto sign in, to avoid login CSRF). `load_user` ignores unconfirmed users. `purge_unverified()` deletes unconfirmed users older than `VERIFY_MINUTES` (20) that hold no years; it runs at startup, at the top of every auth route, and in a `before_request` hook at most once a minute. Signing up again with a pending email never replaces that account (see Sign up safety); signing in with the right password resends the link; a completed password reset also confirms. Tokens come from `serializer(salt)`: `"password-reset"` and `"email-verify"` must stay distinct. `email_allowed()` allows one email per account per `EMAIL_COOLDOWN_SECONDS` (`users.email_sent_at`).

**Emails.** `send_template_email(to, subject, name, **ctx)` renders `templates/email/<name>.txt` and `.html` (tables, inline light colors, dark overrides in a `prefers-color-scheme` block plus Outlook `[data-ogsc]`/`[data-ogsb]`). `mailer.build_message()` builds multipart/alternative with the logo attached inline as `cid:logo@nomadlife` (never a remote URL: `APP_BASE_URL` may be localhost). `send_email()` returns False only on an SMTP failure; without Gmail settings it prints the text version and returns True.

**Day math is centralized.** `compute_stats(year_row, movements)` is the single source of truth for the dashboard and the accountant package. Rules: dates inclusive; days not covered by a movement count toward the base country only once they have passed (future days without a stay are `upcoming`, counted nowhere), while movements count in full, also in the future; a day shared by two stays goes to the stay that started later; ties on start day go to the shorter stay (`stay_order`); `counted` gives the days each movement actually contributes. Countries are compared through `normalize_country()`/`fold()` (accents, case, aliases and ISO codes from `countries.py` `COUNTRY_DATA`); unknown free text is kept as typed.

**Dashboard pagination is display only.** `dashboard()` loads every movement for `compute_stats` and passes `paginate(...)` (key `rows`, not `items`, which Jinja would resolve to the dict method) to the table. The page size (`PER_PAGE_OPTIONS`) is remembered in `session["per_page"]` by `page_size()`. Build dashboard links with `dashboard_url()`: links land on `#movements`, redirects pass `anchor=False` so flash messages stay in view. `back_to_movement()` finds the page that shows a movement using the same `ORDER BY` as the dashboard.

**Sign up safety.** Signing up again for an address that is still waiting for confirmation never replaces that row: it raises `session_version` (so earlier confirmation links, which carry `v`, stop working) and emails the mailbox a choose-your-password link (`send_password_link`, a reset token). `session_version` is also raised when an admin disables an account and is part of `User.get_id()` once non zero, so old sessions never come back. A failed send calls `release_email_wait()`.

**Settings page and limits.** `/settings` (`settings()`, `templates/settings.html`; `/account` GET redirects there and POST is forwarded, for old links and open pages; the email links keep `/account/email/...`) sets the optional first and last name (`profile` action, `clean_name()` keeps zero width joiners and drops blank letters, `NAME_MAX`, `full_name()`, `User.name` for the header), changes the password (current password required; `login_user` again with the new fingerprint so only other sessions end), changes the email through a signed `email-change` link (`confirm_email`; only the newest request, stored in `users.pending_email`, can be confirmed, and only while the email is still the `old` one in the token and the password is unchanged; reset tokens carry the email too), and deletes the account (`delete_account()`, shared with the admin page). Sign ins, current password checks and reset requests first call `take_attempt(kind, email, device)`, which checks the limits and records the attempt in `auth_events` under one write lock (so parallel requests cannot all pass); a right password calls `forgive()`. A successful sign in sets the signed `nomadlife_device` cookie (`remember_device()`); while a browser carries one for that email (`device_for()`), its failures count per device instead of per account, so strangers cannot lock the owner out. Reset requests use kind `forgot`; sign ups use kind `signup` (per IP). Hash and check passwords only through `hash_password()`/`password_matches()`: they cap concurrent scrypt runs (`HASH_SLOTS`), and `password_matches(None, ...)` checks a dummy hash so unknown emails take as long as real ones. Sign up and the email change form answer the same whether or not the address has an account (the owner gets the `account_exists` email). "Sign out everywhere else" (`action=sessions`) raises `session_version`; "Remember me" lasts 30 days. Limits live in `LIMITS` and `LIMIT_WINDOW_MINUTES`. The per IP key uses `request.remote_addr`, so behind a proxy `PROXY_COUNT` enables `ProxyFix`.

**Admin page.** `/admin`, `/admin/users/<id>` (GET: the account page `admin_account`) and `POST /admin/users/<id>` are only for accounts in `ADMIN_EMAILS` (config.env, parsed by `admin_emails()`); everyone else gets a 404 (`require_admin()`). `/admin` lists accounts in a table, `ADMIN_USERS_PER_PAGE` (10) a page, searched by email or name (`search`, through `db.search_like()`) and sorted by the whitelist `ADMIN_USER_SORTS` (`sort`, `dir`); `q` is the separate Security activity filter. Build its links with `admin_url(**values)` and `admin_account_url()`, which drop default values; `admin_list_state()` reads the list state from a query string or form. Quota, plan, disable/enable and delete live on the account page; their forms carry the list state, redirect back to the account page, and a completed delete goes back to the list. The `plan` action sets `users.plan` (only keys of `PLANS`). Per account quota is `users.quota_bytes` (NULL means the quota of the account's plan); always read quotas through `user_quota()`. `users.disabled` makes `load_user` return None and blocks sign in. Admins cannot disable or delete accounts in `ADMIN_EMAILS`.

**Support tickets.** Tables `tickets` (kind in `TICKET_KINDS`, status `open`/`closed`, `created_at`, `updated_at`, `closed_at`, `closed_by`, `user_seen_id`/`admin_seen_id` = last message id seen, for the unread dots) and `ticket_messages` (`from_admin`, `author_id` SET NULL). User routes `/support`, `/support/new`, `/support/<id>` load tickets through `get_ticket_or_404` (owner scoped); admin routes `/admin/support` (filters `status`, `kind`, `q`; sort whitelist `TICKET_SORTS`; links through `admin_support_url()`) and `/admin/support/<id>` go through `require_admin()`. Status changes are conditional updates (`db.execute_rowcount`), and replies re-check the status inside `db.transaction()`: an admin cannot answer a closed ticket without `reopen_reply`, and a user message reopens only below `OPEN_TICKETS_MAX`. Subjects go through `clean_name()`, bodies through `clean_ticket_body()` (both NFC, and `visible()` refuses text of spaces, joiners, blank letters or marks only); limits use `take_attempt("ticket" | "ticket_msg", ticket_limit_key())`, keyed by account id. Emails (`notify_admins`, `notify_user`, templates `ticket_admin`/`ticket_user`) only link to the ticket, never carry its text. Ticket times use the `utcdatetime` filter. Admin search compares with the `casefold()` SQL function registered in `db.get_db()` (`db.search_fold()`: NFC and casefold). Ticket audit events are hidden from the Settings activity list.

**Two-factor.** TOTP (RFC 6238, stdlib only: `totp_code`, `totp_match`, `use_totp_step` which refuses a step already used; secret in `users.totp_secret`, last step in `users.totp_step`). Sign in with a secret stores `session["tfa"]` (uid, fingerprint, session version, remember, next, time) and redirects to `/login/code`; `finish_sign_in()` is the one place that calls `login_user` after a sign in. Wrong codes use `take_attempt("code", email)` (own limits in `LIMITS`), cleared only by a right code (`clear_code_failures`). Setup lives on `/settings` (`2fa_enable`/`2fa_disable`, secret kept in `session["totp_setup"]` as `{"uid", "secret"}` until confirmed, QR from `segno` as a data URI, never inline SVG). `require_admin()` sends admins without a secret to `/settings` (no anchor, so the message stays in view) unless `ADMIN_REQUIRE_2FA` is False (tests of other features only). `flask --app app reset-2fa <email>` removes it.

**Audit log and alerts.** `audit(event, user_id, email, detail, actor)` writes `audit_log` (labels in `AUDIT_LABELS`, pruned after `AUDIT_DAYS` by the purge hook). `security_alert(email, what)` sends `security_alert` emails without the cooldown and never with the user's name. The email change alert carries a signed `email-revert` link (`revert_email`, POST only, 7 days). `send_template_email` adds `first_name` (looked up by the recipient address, verified accounts only) for the "Hi Ada," greeting; mails to an address that is not yet the account's (change_email) pass `first_name=""`.

**Sessions and passwords.** Every sign in goes through `sign_in_user()`, which adds a `user_sessions` row whose id (`User.sid`) is appended to `get_id()` after a `/`; `load_user` refuses a sid without a row or unused for `SESSION_IDLE_DAYS` (ids without a sid, from before 1.2.10, still load). `sign_out()` deletes the row and clears `totp_setup`, `tfa` and `nl_remember`; `stay_signed_in_here()` re-signs this browser (same row, remember choice from `session["nl_remember"]`, set on sign in and by the `user_loaded_from_cookie` signal) and deletes the other rows. New passwords go through `password_problem()` (length, confirm, then `breach_count()` against Have I Been Pwned unless `PWNED_CHECK` is off; sign up runs the network check only after its rate limit). Tests set `PWNED_CHECK` False in `AppTestCase`; a test that builds its own app must too.

**Response headers.** The `security_headers` after request hook sets `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff` and `Referrer-Policy: same-origin` on every response, and `Cache-Control: private, no-store` on every non static response to a signed in user. HTML responses also get `CSP` (scripts only from `static/js`: never add inline scripts, `on*` attributes or `javascript:` URLs; JSON data blocks are fine); other responses, such as receipt PDFs, only get `frame-ancestors 'none'`, since a full policy breaks Chrome's PDF viewer. The saved theme is applied by `static/js/theme-init.js`, loaded in `<head>`.

**Input limits.** City and country go through `clean_place()` and `valid_email()` refuses control and format characters (U+202E and the like). City and country are limited to `PLACE_MAX` (100) characters and a year to `MOVEMENTS_MAX` (1000) stays; `map_pins()` deduplicates with sets, keep it linear.

**File permissions.** The database is chmod 600 in `db.init_db`, receipt folders are made with mode 700, and `runWebApp.sh` runs with `umask 077`.

**Dependencies and CI.** `requirements.txt` is pinned (all transitive packages too, every pin must install on Python 3.10); `.github/workflows/security.yml` runs the tests on 3.10 and 3.12 and pip-audit.

**Uploads and storage.** `detect_type()` checks `FILE_SIGNATURES` and keeps an image under its real image extension. `save_upload()` is the only write path for documents: it measures the upload stream, checks type, empty and the per-receipt limit (on the original), shrinks big photos (`shrink_photo()`: over `PHOTO_MAX_AREA` pixels or `PHOTO_SHRINK_BYTES`, resized to `photo_target()`, never under `PHOTO_MIN_SIDE`, JPEG without metadata, only when smaller; nothing over `PHOTO_MAX_PIXELS` is decoded; one at a time per process, `IMAGE_SLOTS`), writes `UPLOAD_DIR/<user_id>/<uuid>.zip` (`write_receipt_zip()`: one member named by `zip_member_name()`, deflate or stored, unique temp file then `os.replace`), then checks the quota with the ZIP size and inserts inside `db.transaction()` so parallel uploads cannot exceed it; any failure removes the file. `documents.size` is the ZIP on disk (quotas), `format`/`file_size`/`mime` describe the file inside (`doc_format()`); rows from before 1.2.12 point to plain files until `flask --app app zip-receipts` converts them. Downloads are always ZIP (legacy files zipped on the fly); renames rewrite the ZIP into a temporary file first and `os.replace` it under `db.transaction()` only if the row is unchanged; single receipt deletes read and delete the row in one transaction; the package reads members (`package.open_receipt`) and `receipt_readable()` marks damaged ZIPs missing. `display_name()` keeps Unicode names; MIME type comes from the extension, never the client. Deletes remove DB rows first and files after (`remove_files()`). Downloads send `Cache-Control: private, no-store`. Sizes: `mb_setting()` (binary MB), `MAX_RECEIPT_MB` (legacy `MAX_UPLOAD_MB`), `USER_QUOTA_MB`, `MAX_CONTENT_LENGTH` = largest plan receipt limit + 1 MB, narrowed per request in `request_size_limit()` to the user's plan limit + 1 MB; `format_size()` (B, KB, MB, GB) rounds capacities down and rejected sizes up.

**Plans.** `PLANS` in `app.py` (keys `free`, `pro`, `plus`; stored in `users.plan`, unknown keys count as Free). `plan_catalog()` turns them into limits in bytes and feature lists: Free uses `USER_QUOTA_BYTES`/`MAX_RECEIPT_BYTES` from config, paid plans never less. Use `current_plan()`, `receipt_limit()`, `user_quota()` and `next_plan()`; never read `USER_QUOTA_BYTES` or `MAX_RECEIPT_BYTES` directly for a user. `/plan` shows the current plan and the next tier (no payment); the header chip, the storage card "Upgrade" button and the landing Plans section (`plan_card` macro in `_macros.html`) all read the same catalog, and `site_meta()` lists the plans as JSON-LD offers in USD (`PLAN_CURRENCY`). Prices: `PLANS` has the defaults; `POST /admin/plans/<key>` stores overrides in cents in the `plan_prices` table (`parse_price()`, `money()`), which `plan_catalog()` reads through `price_overrides()` (cached on `g`). Templates test `price_cents`/`year_cents`, since `price`/`year` are display strings. Free lists every feature; each paid plan has `includes` (the plan before it) and lists only what it adds, shown as "Everything in <plan>, plus:".

**Dashboard map.** `map_pins(year_row, movements, stats)` groups the year's base and stays into one pin per country, with its days taken from `compute_stats` rows (`COUNTRY_POINTS` in `countries_geo.py`, as left/top percentages); places without a point are returned apart and listed under the map. The land is `static/img/world.svg` used as a CSS mask (`--map-land`), so it follows the theme; pins are buttons with a pure CSS tooltip (`:hover` and `:focus`, so a tap on a phone opens it too; `tip-left`/`tip-right`/`tip-below` near the edges). Zoom (1, 2, 4, 8) lives in `theme.js`: only `.map-land` is scaled inside the clipped `.map-viewport`; pins are positioned in screen pixels from their percentages (parked invisibly inside the map with `is-off` when outside the view, still focusable, and focusing one pans to it), then nudged apart through `--nudge-x`/`--nudge-y` (at most about 7% of the map width). The +, - and whole world buttons (`.map-zoom`, in the card head so they never cover a pin) use `aria-disabled` at the limits; drag pans while zoomed, and + - 0 and the arrow keys work inside the map card. Cities and off map places are deduplicated with `fold()`. `scripts/build_map.py` regenerates both data files from Natural Earth; do not edit them by hand.

**Deletes need two confirmations.** Delete forms use the `ui.delete_form` macro (`templates/_macros.html`, `data-confirm-delete`). `static/js/theme.js` shows a two-step `<dialog>` (native `confirm` fallback) and only then sets `confirm_delete=2`; the server refuses any delete without it (`delete_confirmed()`). Year deletion also needs the typed year (`confirm_year`).

**Accountant package** (`package.py`). `build_package_data()` in `app.py` gathers numbers with `compute_stats` into a `PackageData`; `package.prepare()` builds README, PDF (fpdf2, fonts in `static/fonts`) and CSV files eagerly; `package.stream()` yields the ZIP in chunks through a non-seekable sink, computing SHA-256 for `manifest.csv`. ZIP paths go through `clean_segment()`/`_unique()`/`_check_arcname()`; CSV cells through `csv_safe()`. The package names its `holder` (`package_holder()`: name and email, or the email); `render_pdf` turns on HarfBuzz text shaping only when `_needs_shaping()` finds right to left text. Access is gated in one place: `can_download_package()`, true for plans with `"package": True` in `PLANS` (Pro and Nomad+).

**Frontend.** Server-rendered Jinja with progressive enhancement in `static/js/theme.js` (theme toggle, header user menu (a `<details>`: closes on outside click, Escape and focus out), dismissible flash messages, delete dialog, country combobox, file size/quota checks, download busy state via the `nl_download` cookie, share buttons). The combobox reads `#country-data` JSON from `templates/_countries.html`, which is included only on the three pages with country fields. Flags are emoji rendered with the bundled Twemoji Country Flags font (`unicode-range` limited).

**Styles.** `static/css/style.css` defines color tokens three times: `:root`, `:root[data-theme="dark"]` and the `prefers-color-scheme: dark` media block. Change all three together. Text colors use the WCAG AA tokens (`--link`, `--success-text`, `--error-text`, `--danger`), not the raw accent colors. `[hidden]` is forced to `display: none !important` because rules like `.field { display: flex }` would otherwise override it.

**SEO and public pages.** Only the landing page (`/`) is indexable; `base.html` defaults the robots block to `noindex`. `site_meta()` builds Open Graph, Twitter card, share links and JSON-LD from `APP_BASE_URL` (never from the request Host). `PRIVATE_PATHS` feeds `/robots.txt`; `/sitemap.xml` lists the landing page. The 404 page is the standalone `static/404.html`, served by the error handler. The signed-in app lives under `/app`, `/plan`, `/settings`, `/admin`, `/year/...`, `/movements/...`, `/documents/...`.

## Conventions

- No em dashes or en dashes anywhere: code, UI text, markdown, commit messages.
- Releases follow semantic versioning from 1.0.0 (stable): patch bumps for fixes. Update `APP_VERSION` in `app.py`, the "Current version" line in `README.md`, and add a `CHANGELOG.md` entry; then commit and push to `master`.
- Document new settings in `config.env.example` and the README configuration table. `config.env`, `data/` and `uploads/` are git-ignored.
