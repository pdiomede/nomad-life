# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Nomad Life is a Flask + SQLite web app that tracks the days a digital nomad spends in each country per solar year and stores receipts. No build step, no JS bundler, no linter configured.

## Commands

```bash
./runWebApp.sh                      # create config.env and .venv if missing, install requirements when
                                    # requirements.txt changes, free APP_PORT, start the app
.venv/bin/python -m unittest        # full test suite (tests/)
.venv/bin/python -m unittest tests.test_package.PackageContentsTests.test_structure_and_order   # one test
.venv/bin/python -W ignore::ResourceWarning -m unittest   # quieter output
FLASK_DEBUG=1 .venv/bin/python app.py                     # debug mode (templates reload)
.venv/bin/python scripts/build_map.py                     # regenerate static/img/world.svg and countries_geo.py (downloads Natural Earth)
.venv/bin/python scripts/backup.py --dest DIR --keep 14   # one tar.gz with nomad.db and .secret_key (paths from config.env);
                                                          # --with-receipts adds uploads/, which is otherwise backed up off-site as it is
.venv/bin/flask --app app zip-receipts                    # convert pre 1.2.12 plain receipt files to ZIP
.venv/bin/flask --app app reset-2fa <email>               # remove an account's two-factor secret
.venv/bin/flask --app app forget-test-billing [--dry-run] # with live Stripe keys: forget test mode subscriptions and customers
./checkFakeUsers.sh [--dry-run] [--min-age-hours N]       # = flask check-fake-users: report fake accounts, ask, delete
.venv/bin/python scripts/docs_screenshots.py [name ...]   # remake static/img/docs/*.webp and shots.json
                                                          # (demo app + headless Chrome via Node 22, docs_screenshots.mjs)
.venv/bin/pip-audit -r requirements.txt                   # what CI runs (pip install pip-audit first)
```

- Tests: a feature gets its own file (`tests/test_<feature>.py`); the fixes of a release go in `tests/test_fixes_<version without dots>.py` (for example `test_fixes_1212.py`), security fixes in `test_security_<version>.py`.
- Races and "deleted meanwhile" are tested by patching a helper the route calls (`hash_password`, `password_matches`, `clean_ticket_body`, `clean_place`, `ticket_ref`) so it first writes through a second connection (`other_connection()` in `tests/test_fixes_158.py`, with `PRAGMA foreign_keys = ON`).
- After `signup()`, `self.client` is signed in and carries a `nomadlife_device` cookie: use `self.app.test_client()` for a second person, for sign up or forgot password, and for sign in failures that must count per account (a device locks after 5).
- `age_emails()` backdates `email_sent_at` by 61 s; it does not clear it.
- With `EMAIL_IN_BACKGROUND` on, Forgot password emails start only after `resp.close()` (the test client never closes responses).
- Layout fixes are tested by asserting the CSS rule text; check them in headless Chrome by reusing the `Cdp` class in `scripts/docs_screenshots.mjs` (Node 22).
- The full suite takes about 2.5 minutes: run the affected files first.
- Production deployment (gunicorn, nginx, systemd, backups, upgrades) is documented in `setup_vps.md`; server monitoring (Beszel, reached through an SSH tunnel) in `beszel.md`.

- Without `FLASK_DEBUG=1`, Jinja templates are cached: restart the server after editing templates.
- Static CSS/JS are cached for 7 days and linked with `?v=<asset_version>`, a hash of `style.css`, `theme.js`, `theme-init.js` and `docs.js` computed at startup, so edits reach browsers after a server restart without a version bump.
- `config.env` wins over exported shell variables for every key it contains (`load_dotenv(..., override=True)`); `runWebApp.sh` also reads `APP_PORT` with the same parser and exports it. To point a manual server at a scratch database, pass overrides to `create_app({...})` instead of environment variables.

## Architecture

**Single Flask module.** `app.py` holds config, helpers and all routes (`register_routes`). It ends with `app = create_app()`, so importing `app` loads `config.env` and initializes `data/nomad.db`. Tests call `create_app({...})` with overrides; `tests/helpers.py` (`AppTestCase`) gives each test a temporary database and upload folder with CSRF disabled, blanks the Gmail settings (`config.env` may hold real ones), records emails in `self.outbox` instead of sending, and its `signup()` goes through the confirmation link and signs in (new accounts are on Free: call `self.set_plan("pro")` before testing the accountant package; `age_emails()` skips the one minute email cooldown).

**Database** (`db.py`). One sqlite connection per request on `g`. The database runs in WAL mode (`use_wal()` in `init_db`, stored in the file; a busy database at start only logs) with `synchronous = NORMAL` per connection: readers and the writer never wait for each other. Copy it only with `scripts/backup.py` (`copy_database()` reads what is still in `nomad.db-wal`, falls back to a normal connection when a stopped app left no `-shm`, and stores a self-contained rollback journal copy); a restore deletes `nomad.db-wal` and `nomad.db-shm` first. The SQL key functions (`search_fold`, `sort_fold`, `ip_sort_key`) are `lru_cache`d (`KEY_CACHE`). `idx_audit_confirmed` is a partial index (`WHERE event = 'account_confirmed'`): queries must name that event as the literal for SQLite to use it. `query()` reads, `execute()` commits (and rolls back on error), `transaction()` runs `BEGIN IMMEDIATE` for check-then-write sequences: a limit or one time check (movement and ticket caps, reset and email change links, "only if still open") must be repeated inside it, or be a condition of the UPDATE with its rowcount checked. Never do slow work (file rewrites, hashing, email) while holding it. `try_execute()` is for housekeeping that may be skipped when the database is busy (the session last seen stamp, the minute purge, the ticket seen marks), so a page view never fails behind another writer. Schema is `CREATE TABLE IF NOT EXISTS` in `SCHEMA`; there is no migration framework. New tables go straight into `SCHEMA` (created on every start). New columns go in `SCHEMA` and in `db.MIGRATIONS` (add column, backfill), which `migrate()` applies on every start, idempotently and under `BEGIN IMMEDIATE`. Nothing in `SCHEMA` may reference a migrated column, because old databases run `SCHEMA` before the column exists: indexes and triggers on migrated columns go in `db.AFTER_MIGRATIONS` (created after `MIGRATIONS` on every start; `REPLACED_TRIGGERS` are dropped). Foreign keys cascade (years -> movements -> documents), enabled per connection.

**Ownership.** Every private query is scoped by `user_id`. Use `get_year_or_404`, `get_movement_or_404`, `get_document_or_404`: other users' data must return 404, never 403. A POST from a page left open after its year, movement or receipt was deleted (`movement_new`, `movement_edit`, `base`, `document_delete`/`document_edit` through `document_gone()`) redirects with a message instead; another user's id gets the same redirect, so nothing tells the two apart. Admin account actions likewise check the changed rows (and `delete_account()` returns False when the account was already gone).

**Auth.** Flask-Login with `User.get_id()` = `"<id>:<password fingerprint>"`, so a password reset invalidates every other session and remember cookie. Reset tokens (itsdangerous) carry the same fingerprint. Cookie names are app specific (`nomadlife_session`, `nomadlife_remember`), `SameSite=Lax`, and `Secure` when `APP_BASE_URL` is `https://`. All POST forms carry the Flask-WTF CSRF token; tokens live as long as the session (`WTF_CSRF_TIME_LIMIT=None`), and a stale token on sign out still signs out. Redirects after sign in go through `safe_next()` (same site paths only, no control characters), and the unauthorized handler only puts GET pages in `next`. `<int:...>` URL parts are capped to SQLite's range (`DbIntConverter`), so huge ids are a 404.

**Email confirmation.** Sign up creates the user with `verified_at` NULL and emails a `/verify/<token>` link; it does not sign in. `GET /verify/<token>` only shows a "Confirm my account" button (company mail scanners open every link); the POST confirms, as for the email change undo link. Confirming sets `verified_at` and sends the user to sign in (no auto sign in, to avoid login CSRF). `load_user` ignores unconfirmed users. `purge_unverified()` deletes unconfirmed users older than `VERIFY_MINUTES` (20) that hold no years; it runs at startup, at the top of every auth route, and in a `before_request` hook at most once a minute. Signing up again with a pending email never replaces that account (see Sign up safety); signing in with the right password resends the link; a completed password reset also confirms. Tokens come from `serializer(salt)`: `"password-reset"` and `"email-verify"` must stay distinct. `email_allowed()` allows one email per account per `EMAIL_COOLDOWN_SECONDS` (`users.email_sent_at`).

**Emails.** `send_template_email(to, subject, name, **ctx)` renders `templates/email/<name>.txt` and `.html` (tables, inline light colors, dark overrides in a `prefers-color-scheme` block plus Outlook `[data-ogsc]`/`[data-ogsb]`). `mailer.build_message()` builds multipart/alternative with the logo attached inline as `cid:logo@nomadlife` (never a remote URL: `APP_BASE_URL` may be localhost). `send_email()` verifies Gmail's certificate (`ssl.create_default_context()`; smtplib's default checks nothing) and returns False only when sending failed (a failed QUIT after the message was accepted is a success); without Gmail settings it prints the text version and returns True. `send_template_email(..., background=True, on_failure=...)` renders in the request and sends from a thread when `EMAIL_IN_BACKGROUND` (off in `AppTestCase`): sign up uses it (and hashes the password and renders an email for every address) so a registered address does not answer sooner or later than an unknown one. "Forgot password" does nothing for the address during the request: `after_answer(work)` runs the lookup, the cooldown claim and the email for every address from a thread started once the server closes the response (`call_on_close`; a test with `EMAIL_IN_BACKGROUND` on calls `resp.close()`). Password links of an account still waiting for confirmation give its real deadline (`minutes`), not the reset token's hour.

**Day math is centralized.** `compute_stats(year_row, movements)` is the single source of truth for the dashboard and the accountant package. Rules: dates inclusive; days not covered by a movement count toward the base country only once they have passed (future days without a stay are `upcoming`, counted nowhere), while movements count in full, also in the future; a day shared by two stays goes to the stay that started later; ties on start day go to the shorter stay (`stay_order`); `counted` gives the days each movement actually contributes. `assign_days()` (who gets each day) is shared by `compute_stats` and the overlap alert (`compute_stats` returns it as `day_owner`, which `dashboard()` passes to `movement_overlaps()` so it runs once; `parse_date()` caches stored dates, only text of a date's length): `movement_overlaps()` lists the pairs `shares_days()` reports (more than a travel day, one ending the day the other begins), at most `OVERLAP_REPORT_MAX` in detail, and `overlap_report()` writes the dashboard dialog's text; the warning on save (`overlap_notes()`) uses the same rule and names at most `OVERLAP_NOTES_MAX` stays (flash messages live in the session cookie). Countries are compared through `normalize_country()`/`fold()` (accents, case, hyphens as spaces, "&" as "and", aliases and ISO codes from `countries.py` `COUNTRY_DATA`; `fold` in theme.js must give the same key); unknown free text is kept as typed.

**Dashboard pagination is display only.** `dashboard()` loads every movement for `compute_stats` and passes `paginate(...)` (key `rows`, not `items`, which Jinja would resolve to the dict method) to the table. The page size (`PER_PAGE_OPTIONS`) is remembered in `session["per_page"]` by `page_size()`. Build dashboard links with `dashboard_url()`: links land on `#movements`, redirects pass `anchor=False` so flash messages stay in view. `back_to_movement()` finds the page that shows a movement using the same `ORDER BY` as the dashboard.

**Sign up safety.** Signing up again for an address that is still waiting for confirmation never replaces that row: it raises `session_version` (so earlier confirmation links, which carry `v`, stop working) and emails the mailbox a choose-your-password link (`send_password_link`, a reset token). Sign up and Forgot password check `honeypot_filled()` first (the off screen `HONEYPOT_FIELD`, `ui.honeypot()`: the usual answer, no account, no email; never give it a name password managers fill, such as `website`) and `captcha_passed()` after the cheap checks and before `take_attempt` (hCaptcha, `ui.captcha()` and `static/js/captcha.js`, which draws the widget with `render=explicit` and again on a theme change unless it is solved; off unless `HCAPTCHA_SITEKEY` and `HCAPTCHA_SECRET` are both set, blanked in `AppTestCase`, and a test that builds its own app and posts these forms must blank them too; an empty answer fails without a network call; `remoteip` is sent only when `client_ip()` is an address, since hCaptcha refuses a right answer with `remoteip=unknown`; `captcha.js` says so when hCaptcha's script cannot load; only an unreachable hCaptcha or a 5xx lets the form through, any other HTTP status, such as 429, fails; `HCAPTCHA_CONFIG_ERRORS` are logged as errors). Both forms carry `data-submit-once`, since an hCaptcha answer works once. `app.logger` writes from WARNING up, so `logger.info` lines never show: log refusals as warnings. Sign up then refuses `dotted_gmail()` addresses silently (more than `GMAIL_MAX_DOTS` dots before the `@` on `GMAIL_DOMAINS`, the Gmail dot trick), before `take_attempt`. Render those two pages through `captcha_page()`, which sets `g.captcha` so `security_headers` sends `CAPTCHA_CSP`. `session_version` is also raised when an admin disables an account and is part of `User.get_id()` once non zero, so old sessions never come back. A failed send calls `release_email_wait()`.

**Settings page and limits.** `/settings` (`settings()`, `templates/settings.html`; `/account` GET redirects there and POST is forwarded, for old links and open pages; the email links keep `/account/email/...`) sets the optional first and last name (`profile` action, `clean_name()` keeps zero width joiners and drops blank letters, `NAME_MAX`, `full_name()`, `User.name` for the header), changes the password (current password required; `login_user` again with the new fingerprint so only other sessions end), changes the email through a signed `email-change` link (`confirm_email`: GET only shows a **Confirm my new email** button, as for `/verify`, since mail scanners open links; the POST applies it; only the newest request, stored in `users.pending_email`, can be confirmed, and only while the email is still the `old` one in the token and the password is unchanged; reset tokens carry the email too), and deletes the account (`delete_account()`, shared with the admin page). Sign ins, current password checks and reset requests first call `take_attempt(kind, email, device)`, which checks the limits and records the attempt in `auth_events` under one write lock (the key holds the address, so sign in cuts the typed one to 255 characters) (so parallel requests cannot all pass); a right password calls `forgive()`. A successful sign in sets the signed `nomadlife_device` cookie (`remember_device()`); while a browser carries one for that email (`device_for()`), its failures count per device (key `device:<email>:<id>`, so a password reset lifts every device's lock) instead of per account, so strangers cannot lock the owner out. Reset requests use kind `forgot`; sign ups use kind `signup` (per IP). Hash and check passwords only through `hash_password()`/`password_matches()`: they cap concurrent scrypt runs (`HASH_SLOTS`), and `password_matches(None, ...)` checks a dummy hash so unknown emails take as long as real ones. Sign up and the email change form answer the same whether or not the address has an account (the owner gets the `account_exists` email). "Sign out everywhere else" (`action=sessions`) raises `session_version`; "Remember me" lasts 30 days. Limits live in `LIMITS` and `LIMIT_WINDOW_MINUTES`. The per IP key uses `request.remote_addr`, so behind a proxy `PROXY_COUNT` enables `ProxyFix`.

**Admin page.** `/admin`, `/admin/users/<id>` (GET: the account page `admin_account`) and `POST /admin/users/<id>` are only for accounts in `ADMIN_EMAILS` (config.env, parsed by `admin_emails()`); everyone else gets a 404 (`require_admin()`). `/admin` lists accounts in a table, `ADMIN_USERS_PER_PAGE` (10) a page, searched by email or name (`search`, through `db.search_like()`) and sorted by the whitelist `ADMIN_USER_SORTS` (`sort`, `dir`). The Security activity table below it (`activity_page()`, `ui.activity_table`) is searched by `q` (`activity_where()`: an account's email gives its history by user id, plus events under the address that belong to no account, never those of another account that used it, live or deleted; anything else is a LIKE search on the events' email, actor, IP and detail, plus the events whose `AUDIT_LABELS` name or key contains it, so "fake" or "password changed" work), sorted by `AUDIT_SORTS` (`asort`, `adir`; IPs through the `ip_sort_key()` SQL function) and paged in SQL with `paged()` (`apage`, `ADMIN_AUDIT_PER_PAGE` = 20), never loaded whole: the page is chosen in a subquery before the LEFT JOIN with users. The `fake` key (`ADMIN_FAKE_FILTERS`: all, `only`, `hide`) filters the accounts table to the accounts `fake_user_sql()` flags; `admin_accounts()` adds `suspect` and `fake_reason` for the red **Likely fake** chip. `admin_where(state)` builds the accounts table's search and fake filter; with the Suspected fake filter on, `POST /admin/suspects/delete` (`admin_delete_suspects`, the "Delete these N accounts" bar) deletes exactly what that view lists, after the two step dialog with the number of accounts typed (`confirm_count`), for the list as it was when the page was made (`asof`, UTC, from `utc_now_text()`; `fake_user_sql(..., asof=)` fixes "24 hours ago" to it, so an account passing the line meanwhile is neither counted nor deleted): it lists, compares the count, deletes with the rule repeated and writes the audit rows in one `db.transaction()` (`audit(..., conn=conn)` records inside a transaction), one `admin_delete_fake` per account and one `admin_fake_cleanup` summary; a changed list deletes nothing. `check-fake-users` records the same two events. The Security Activity gear menu (`details[data-menu]`, closed by the same theme.js code as the user menu; items `user-menu-item` with CSS mask icons `menu-export`/`menu-purge`) links to `GET /admin/activity/export?range=30|all` (CSV streamed in `AUDIT_EXPORT_CHUNK` rows up to the newest id at the start) and posts `POST /admin/activity/purge` (`delete_confirmed()` and `confirm_word` PURGE; `audit_range_sql()` gives one fixed cutoff for the last `AUDIT_EXPORT_DAYS` days; rows are read outside the lock, the ids deleted are read again under the write lock with the DELETE, and the CSV holds exactly those). The purge answers with the file, sets `nl_download` and a flash; forms with `data-download-reload` make the delete dialog wait for the cookie and reload at the top (no anchor, no scroll restore). CSV cells go through `package.csv_safe()`; a purge also removes `account_confirmed` events, which the Likely fake delay reads. Both tables' state lives in one dict: `admin_list_state()` reads all nine keys from a query string or form, `admin_url(**values)` and `admin_account_url()` drop the defaults (`admin_defaults`), and `admin_hidden(state, *skip)` gives the hidden fields a form must carry. Alphabetical sorts use the `sort_fold()` SQL function (case and accents ignored), never `COLLATE NOCASE`. Quota, plan, disable/enable and delete live on the account page; their forms carry the list state, redirect back to the account page, and a completed delete goes back to the list (so does enabling a never confirmed account: `purge_unverified()` removes it at once once its 20 minutes are over). The `plan` action sets `users.plan` (only keys of `PLANS`). `users.signup_ip` (set on sign up, empty before 1.4.0) and `users.last_login_ip` (set in `finish_sign_in()`) come from `client_ip()`; the accounts table shows them and its search matches them. In the accounts table, on the account page and in `ui.activity_table` (both admin pages) they open `ip_lookup_url()` (ipinfo.io, public addresses only, new tab) through the `ui.ip_link` macro (screen reader text in `aria-label`, never hidden text, which a copy would include); the account page adds a **Same IP** link to the accounts search. Per account quota is `users.quota_bytes` (NULL means the quota of the account's plan); always read quotas through `user_quota()`. `users.disabled` makes `load_user` return None and blocks sign in. `flask check-fake-users` (`./checkFakeUsers.sh`, which runs the first Python that can load the app: `$PYTHON`, the active virtual environment, `.venv`, `python3`) lists accounts matching `FAKE_USER_WHERE` (confirmed, never signed in, no years, documents or tickets, not disabled, Free without a custom quota) that are not admins and older than `FAKE_MIN_AGE_HOURS`, with the confirmation delay from `audit_log` (`fake_user_candidates()`, "scanner" under `SCANNER_SECONDS`); it deletes only after two answers and repeats the rule in the DELETE itself. `fake_user_sql(admins, min_age_hours)` is that one rule (`FAKE_USER_WHERE`, the age and the admins left out) for the tool, its DELETE and the admin chip and filter, so they never disagree. Admins cannot disable or delete accounts in `ADMIN_EMAILS`.

**Support tickets.** Tables `tickets` (kind in `TICKET_KINDS`, status `open`/`closed`, `created_at`, `updated_at`, `closed_at`, `closed_by`, `user_seen_id`/`admin_seen_id` = last message id seen, for the unread dots) and `ticket_messages` (`from_admin`, `author_id` SET NULL). Tickets are numbered per year, `2026-1` (`ref_year`, `ref_seq`): the database sets them, through the `tickets_number` trigger and the `ticket_counters` table (numbers are never reused, also after a deleted account), with a unique index; `ticket_ref()` (also a Jinja filter) shows the number and `ticket_args()`/`ticket_url()` build links. User routes `/support`, `/support/new`, `/support/<year>-<seq>` load tickets through `get_ticket_or_404(year, seq)` (owner scoped); admin routes `/admin/support` (filters `status`, `kind`, `q`, where `2026-3` finds that ticket and a whole email only that account; sort whitelist `TICKET_SORTS`; links through `admin_support_url()`) and `/admin/support/<year>-<seq>` go through `require_admin()`. Links from before 1.3.1, `/support/<id>` and `/admin/support/<id>`, answer 307 to the new address. Inside the handlers the row `id` keeps doing the internal work (messages keep their foreign key on it). Status changes are conditional updates (`db.execute_rowcount`), and replies re-check the status inside `db.transaction()`: an admin cannot answer a closed ticket without `reopen_reply`, and a user message reopens only below `OPEN_TICKETS_MAX`. Subjects go through `clean_name()`, bodies through `clean_ticket_body()` (both NFC, and `visible()` refuses text of spaces, joiners, blank letters or marks only); limits use `take_attempt("ticket" | "ticket_msg", ticket_limit_key())`, keyed by account id. Emails (`notify_admins`, `notify_user`, templates `ticket_admin`/`ticket_user`) only link to the ticket, never carry its text. Ticket times use the `utcdatetime` filter. The lists' state travels with the ticket links (`admin_support_args()`, `support_list_args()`), so Back and the redirects after an action return to the same view. `duplicate_message()` (and the matching check in `support_new`) makes the same ticket or message from the same person within `DUPLICATE_SECONDS` count as already sent, inside the write transaction; the forms also carry `data-submit-once` (theme.js). The conversation is a chat laid out by `chat_rows()` (a template global: side `mine`, party, sender, groups within `CHAT_GROUP_SECONDS`, UTC days), styled with the `--bubble-user`/`--bubble-support` tokens (white text). Admin search compares with the `casefold()` SQL function registered in `db.get_db()` (`db.search_fold()`: NFC and casefold). Ticket audit events are hidden from the Settings activity list.

**Two-factor.** TOTP (RFC 6238, stdlib only: `totp_code`, `totp_match`, `use_totp_step` which refuses a step already used; secret in `users.totp_secret`, last step in `users.totp_step`). Sign in with a secret stores `session["tfa"]` (uid, fingerprint, session version, remember, next, time) and redirects to `/login/code`; `finish_sign_in()` is the one place that calls `login_user` after a sign in. Wrong codes use `take_attempt("code", email)` (own limits in `LIMITS`), cleared only by a right code (`clear_code_failures`). Setup lives on `/settings` (`2fa_enable`/`2fa_disable`; the key being set up is kept in this browser's `user_sessions.totp_setup` through `totp_setup_secret()` until confirmed, never in the session cookie, which is signed but readable; QR from `segno` as a data URI, never inline SVG). Code fields carry no `pattern` (the server takes full width digits). `require_admin()` sends admins without two-factor to `/settings` (no anchor, so the message stays in view) unless `ADMIN_REQUIRE_2FA` is False (tests of other features only). `flask --app app reset-2fa <email>` removes it (app and passkeys).

**Passkeys.** WebAuthn through py_webauthn (`webauthn`, pinned with its dependencies) as the other second step, never passwordless: two-factor is on while `has_two_factor(row)` (a `totp_secret` or a `passkeys` row); use it, never `totp_secret` alone, wherever "two-factor is on" is meant (sign in, `pending_two_factor()`, `require_admin()`, the admin `has_2fa`, the CLI). `passkey_site()` gives the RP ID and origin from `APP_BASE_URL` (the request's address only when it is empty). Each ceremony's challenge is a `passkey_challenges` row (only the newest per account and kind; `use_passkey_challenge()` deletes it, one use, within `PASSKEY_CEREMONY_SECONDS`), since a session cookie sent again would hold the challenge again. Adding: `POST /settings/passkeys/options` checks the password and answers JSON, `static/js/passkeys.js` makes the passkey and posts it as `credential` with action `passkey_add`, which checks the password again, the session's `passkey_reg` (uid, password fingerprint, challenge) and inserts under `db.transaction()` with `PASSKEYS_MAX`, the credential id and the account (`password_hash`, `session_version`) checked again; other sessions end. Sign in: `/login/code` offers the passkey and/or the code, `POST /login/passkey/options` and `POST /login/passkey` (failures count as `take_attempt("code")`; the counter is updated with `WHERE sign_count = ?`). Rename (`passkey_rename`) needs no password; remove (`passkey_remove`) needs it and the two step dialog. Undoing an email change and `reset-2fa` delete the passkeys too; security alerts never carry a passkey's name. Tests sign with `tests/soft_authenticator.py` (real P-256 signatures), so py_webauthn's checks run.

**Audit log and alerts.** `audit(event, user_id, email, detail, actor)` writes `audit_log` (labels in `AUDIT_LABELS`, pruned after `AUDIT_DAYS` by the purge hook). `security_alert(email, what)` sends `security_alert` emails without the cooldown and never with the user's name; nor does the password link of an undo (`send_password_link(..., first_name="")`). The email change alert carries a signed `email-revert` link (`revert_email`, POST only, 7 days); undoing also replaces the password with an unusable one and turns two-factor sign in off (whoever made the change knew the password, and may have set up their own phone), so only the emailed reset link sets a new one; changes are numbered (`email_changes` rows, created by `confirm_email`; the link carries the number as `n`), so it applies while its change stands, from whatever address the account moved on to, and undoes every later change too (`undo_status()`: "back", "ok" or "stale", checked again under the write lock; `undo_already_done()` answers a link pressed twice): a second change cannot take the owner's way back, and the undo of a later change cannot take the account from the owner. Links without `n` (from before) work only while the account still uses the new address. The purge hook prunes the rows after the links' 7 days. Writes that rely on what the request read earlier repeat it as a condition and check the rowcount (password change, two-factor on, starting an email change and deleting the account in Settings, `delete_account(id, password_hash)`: `AND password_hash = ?`; a reset by link: `AND password_hash = ? AND email = ?`; signing up again for a pending address: `AND verified_at IS NULL`; `finish_sign_in`; confirming an account); a signed in account deleted mid-request goes through `account_gone()`. `send_template_email` adds `first_name` (looked up by the recipient address, verified accounts only) for the "Hi Ada," greeting; mails to an address that is not yet the account's (change_email) pass `first_name=""`.

**Sessions and passwords.** Every sign in goes through `sign_in_user()`, which adds a `user_sessions` row whose id (`User.sid`) is appended to `get_id()` after a `/`; `load_user` refuses a sid without a row or unused for `SESSION_IDLE_DAYS` (ids without a sid, from before 1.2.10, still load). `sign_out()` deletes the row and clears `totp_setup`, `tfa` and `nl_remember`; `stay_signed_in_here()` re-signs this browser (same row, remember choice from `session["nl_remember"]`, set on sign in and by the `user_loaded_from_cookie` signal) and deletes the other rows. New passwords go through `password_problem()` (length, confirm, then `breach_count()` against Have I Been Pwned unless `PWNED_CHECK` is off; sign up runs the network check only after its rate limit). Tests set `PWNED_CHECK` False in `AppTestCase`; a test that builds its own app must too.

**Response headers.** The `security_headers` after request hook sets `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff` and `Referrer-Policy: same-origin` on every response, and `Cache-Control: private, no-store` on every non static response to a signed in user, `Permissions-Policy` (`PERMISSIONS_POLICY`) on every response, and `Retry-After` on a 429 (seconds from `g.retry_after`, which `too_many_message()` sets). HTML responses also get `CSP` (scripts only from `static/js`: never add inline scripts, `on*` attributes or `javascript:` URLs; JSON data blocks are fine; only the Sign up and Forgot password pages get `CAPTCHA_CSP`, which adds the hCaptcha hosts); other responses, such as receipt PDFs, only get `frame-ancestors 'none'`, since a full policy breaks Chrome's PDF viewer. The saved theme is applied by `static/js/theme-init.js`, loaded in `<head>`.

**Input limits.** City and country go through `clean_place()` and `valid_email()` refuses control and format characters (U+202E and the like). City and country are limited to `PLACE_MAX` (100) characters and a year to `MOVEMENTS_MAX` (1000) stays; `map_pins()` deduplicates with sets, keep it linear.

**File permissions.** The database is chmod 600 in `db.init_db`, receipt folders are made with mode 700, and `runWebApp.sh` runs with `umask 077`.

**Dependencies and CI.** `requirements.txt` is pinned (all transitive packages too, every pin must install on Python 3.10); `.github/workflows/security.yml` runs the tests on 3.10 and 3.12 and pip-audit.

**Uploads and storage.** `detect_type()` checks `FILE_SIGNATURES` and keeps an image under its real image extension. `save_upload()` is the only write path for documents: it measures the upload stream, checks type, empty and the per-receipt limit (on the original), shrinks big photos (`shrink_photo()`: over `PHOTO_MAX_AREA` pixels or `PHOTO_SHRINK_BYTES`, resized to `photo_target()`, never under `PHOTO_MIN_SIDE`, JPEG without metadata, only when smaller; nothing over `PHOTO_MAX_PIXELS` is decoded; one at a time per process, `IMAGE_SLOTS`), writes `UPLOAD_DIR/<user_id>/<uuid>.zip` (`write_receipt_zip()`: one member named by `zip_member_name()`, deflate or stored, unique temp file then `os.replace`), then checks the quota with the ZIP size and inserts inside `db.transaction()` so parallel uploads cannot exceed it; any failure removes the file. `documents.size` is the ZIP on disk (quotas), `format`/`file_size`/`mime` describe the file inside (`doc_format()`); rows from before 1.2.12 point to plain files until `flask --app app zip-receipts` converts them. Downloads are always ZIP (legacy files zipped on the fly); renames rewrite the ZIP into a temporary file first and `os.replace` it under `db.transaction()` only if the row is unchanged; single receipt deletes read and delete the row in one transaction; the package reads members (`package.open_receipt`) and `receipt_readable()` marks damaged ZIPs missing (catch `package.RECEIPT_ERRORS`: a damaged header raises RuntimeError or NotImplementedError, not only BadZipFile). Renaming between .jpg and .jpeg keeps one extension; a name whose stem is not `visible()` is refused. `display_name()` keeps Unicode names; MIME type comes from the extension, never the client. Deletes remove DB rows first and files after (`remove_files()`). Downloads send `Cache-Control: private, no-store`. Sizes: `mb_setting()` (binary MB), `MAX_RECEIPT_MB` (legacy `MAX_UPLOAD_MB`), `USER_QUOTA_MB`, `MAX_CONTENT_LENGTH` = largest plan receipt limit + 1 MB, narrowed per request in `request_size_limit()` to the user's plan limit + 1 MB; `format_size()` (B, KB, MB, GB) rounds capacities down and rejected sizes up.

**Plans.** `PLANS` in `app.py` (keys `free`, `pro`, `plus`; stored in `users.plan`, unknown keys count as Free). `plan_catalog()` turns them into limits in bytes and feature lists: Free uses `USER_QUOTA_BYTES`/`MAX_RECEIPT_BYTES` from config, paid plans never less. Use `current_plan()`, `receipt_limit()`, `user_quota()` and `next_plan()`; never read `USER_QUOTA_BYTES` or `MAX_RECEIPT_BYTES` directly for a user. `/plan` shows the current plan and the next tier (no payment); the header chip, the storage card "Upgrade" button and the landing Plans section (`plan_card` macro in `_macros.html`) all read the same catalog, and `site_meta()` lists the plans as JSON-LD offers in USD (`PLAN_CURRENCY`). Prices: `PLANS` has the defaults, in cents (`price_cents`, `year_cents`; saving the defaults, or empty fields, removes the override); `POST /admin/plans/<key>` stores overrides in cents in the `plan_prices` table (`parse_price()`, `money()`), which `plan_catalog()` reads through `price_overrides()` (cached on `g`). Templates test `price_cents`/`year_cents`, since `price`/`year` are display strings. Free lists every feature; each paid plan has `includes` (the plan before it) and lists only what it adds, shown as "Everything in <plan>, plus:".

**Billing (Stripe).** Paid plans are yearly only (`PLANS` `year_cents`; `price`/`price_cents` in `plan_catalog()` are the yearly price, `month` a twelfth for "about $0.83 a month"; admin overrides are yearly, `plan_prices.month_cents` kept as a twelfth for old databases). `billing_settings()` reads the four `STRIPE_*` keys (all or none; `billing_on()`; blanked in `AppTestCase`). Stripe's API is called with urllib (`stripe_api()`, form encoded by `stripe_form()`, an `Idempotency-Key` per POST, the pinned `STRIPE_API_VERSION` header on every request, Stripe's refusal message in `g.stripe_error`), no SDK. `POST /billing/checkout` makes or reuses the account's Stripe customer (`users.stripe_customer_id`) and a Checkout Session (subscription mode, `automatic_tax`, `tax_id_collection`, `consent_collection` terms checkbox with a fallback to plain text while Stripe has no Terms URL, the user id from the server in `client_reference_id` and the subscription metadata) and redirects 303; `POST /billing/portal` opens the customer portal (cancel, switch, card, invoices). **The webhook is the only writer of a paid plan:** `POST /billing/webhook` (CSRF exempt through `app.extensions["csrf"]`) checks `stripe_signature_ok()` (HMAC SHA-256 of `t.body`, 5 minutes), for `customer.subscription.*` reads the subscription as it is now from Stripe before taking the lock (events may arrive out of order; unreachable: 500, so Stripe retries), records the event id in `billing_events` (once only), and in one `db.transaction()` `apply_subscription()` upserts `subscriptions` (ignores events older than `last_event_at`, never moves a stored subscription to another account, maps the price through `price_plans()`) and sets `users.plan` to the best plan of the account's subscriptions in `PAID_STATUSES` (else `free`); audit rows `plan_upgraded`/`plan_changed`/`plan_downgraded`/`plan_renewed`/`payment_failed` with actor Stripe, then `billing_notice()` emails. `open_subscription()` (`OPEN_STATUSES`: paid ones plus `unpaid` and `paused`, which Stripe may still charge) blocks a second checkout and deleting the account (Settings and admin); `active_subscription()` (`PAID_STATUSES`) is what pays for a plan. The admin's Stripe dashboard link goes to test mode for any key containing `_test_` (`sk_test_`, `rk_test_`). A cancellation is `cancel_at_period_end` (classic billing) or `cancel_at` (flexible billing, the portal's default now): `apply_subscription()` stores either as `cancel_at_period_end` = 1 with the end day in `current_period_end`. A stored customer Stripe no longer knows ("No such customer": test mode, or deleted in the dashboard) is forgotten by `stripe_customer_gone()`, and checkout makes a new one (`new_stripe_customer(row, retry=True)`, a fresh idempotency key); an email change and its undo give the customer the new address (`stripe_sync_email()`). `flask forget-test-billing` (live keys only) forgets the test mode rows Stripe's live account answers "No such ..." for. Setup steps and the test account's ids live in `stripe.md`. Never set a paid plan from the browser. The legal pages (`/terms`, `/privacy`, `/refunds`, `LEGAL_PAGES`, `templates/legal/`, figures from `REFUND_DAYS`, `AUDIT_DAYS` and the `COMPANY` constant) and the footer name Nemax Tech LLC, the seller. Tests: `tests/test_billing.py` signs events with a test secret and patches `stripe_api` (its `event()` also answers the subscription read, `latest=`).

**Dashboard map.** `map_pins(year_row, movements, stats)` groups the year's base and stays into one pin per country, with its days taken from `compute_stats` rows (`COUNTRY_POINTS` in `countries_geo.py`, as left/top percentages); places without a point are returned apart and listed under the map. The land is `static/img/world.svg` used as a CSS mask (`--map-land`), so it follows the theme; pins are buttons with a pure CSS tooltip (`:hover` and `:focus`, so a tap on a phone opens it too; `tip-left`/`tip-right`/`tip-below` near the edges). Zoom (1, 2, 4, 8) lives in `theme.js`: only `.map-land` is scaled inside the clipped `.map-viewport`; pins are positioned in screen pixels from their percentages (parked invisibly inside the map with `is-off` when outside the view, still focusable, and focusing one pans to it), then nudged apart through `--nudge-x`/`--nudge-y` (at most about 7% of the map width). The +, - and whole world buttons (`.map-zoom`, in the card head so they never cover a pin) use `aria-disabled` at the limits; drag pans while zoomed, and + - 0 and the arrow keys work inside the map card. Cities and off map places are deduplicated with `fold()`. `scripts/build_map.py` regenerates both data files from Natural Earth; do not edit them by hand.

**Deletes need two confirmations.** Delete forms use the `ui.delete_form` macro (`templates/_macros.html`, `data-confirm-delete`). `static/js/theme.js` shows a two-step `<dialog>` (native `confirm` fallback) and only then sets `confirm_delete=2`; the server refuses any delete without it (`delete_confirmed()`). Year deletion also needs the typed year (`confirm_year`).

**Accountant package** (`package.py`). `build_package_data()` in `app.py` gathers numbers with `compute_stats` into a `PackageData`; `package.prepare()` builds README, PDF (fpdf2, fonts in `static/fonts`) and CSV files eagerly (every entry deflated, for streaming readers: photos at level 0, `compress_level()`, PDFs 1, text 6); `package.stream()` yields the ZIP in chunks through a non-seekable sink, computing SHA-256 for `manifest.csv`. ZIP paths go through `clean_segment()`/`_unique()`/`_check_arcname()`; CSV cells through `csv_safe()`. The package names its `holder` (`package_holder()`: name and email, or the email); `render_pdf` turns on HarfBuzz text shaping only when `_needs_shaping()` finds right to left text. Access is gated in one place: `can_download_package()`, true for plans with `"package": True` in `PLANS` (Pro and Nomad+).

**Frontend.** Server-rendered Jinja with progressive enhancement in `static/js/theme.js` (theme toggle, header user menu (a `<details>`: closes on outside click, Escape and focus out), dismissible flash messages, delete dialog, country combobox, file size/quota checks, download busy state via the `nl_download` cookie, share buttons). The combobox reads `#country-data` JSON from `templates/_countries.html`, which is included only on the three pages with country fields. Flags are emoji rendered with the bundled Twemoji Country Flags font (`unicode-range` limited). Inter and Outfit are self hosted in `static/fonts/web` (one woff2 per character set from Google Fonts, `@font-face` at the top of `style.css`, Inter variable 400 to 700, `inter-latin` preloaded in `base.html`; `static/404.html` declares the latin ones itself): never link Google Fonts again, the CSP allows `font-src 'self'` only.

**Styles.** `static/css/style.css` defines color tokens three times: `:root`, `:root[data-theme="dark"]` and the `prefers-color-scheme: dark` media block. Change all three together. Text colors use the WCAG AA tokens (`--link`, `--success-text`, `--error-text`, `--danger`), not the raw accent colors. `[hidden]` is forced to `display: none !important` because rules like `.field { display: flex }` would otherwise override it.

**Documentation page.** `/docs` (`docs()`, `templates/docs.html`) is public and indexable. Its contents come from `DOCS_TOC` in `app.py`, which must list every `doc-section`/`doc-sub` in page order (tests/test_docs.py checks it). Every number on the page comes from the app's constants passed by `docs()`, never typed in the text. Screenshots are `static/img/docs/<name>-light.webp` and `-dark.webp` shown by the `shot()` macro (sizes from `shots.json`); regenerate them with `scripts/docs_screenshots.py` instead of editing them. `static/js/docs.js` (search, the `/` shortcut, the contents that follow the reading position) is loaded only there and is part of the `asset_version` hash.

**SEO and public pages.** Only the landing page (`/`), `/docs` and the guides (`/guides`, `/guides/<slug>`) are indexable; `base.html` defaults the robots block to `noindex`. `site_meta()` builds Open Graph, Twitter card, share links and JSON-LD from `APP_BASE_URL` (never from the request Host). `PRIVATE_PATHS` feeds `/robots.txt`; `/sitemap.xml` lists the landing page and `/docs`. Link preview tags come from the `og_title`/`og_description` blocks of `base.html` (the twitter tags repeat them through `self.og_title()`), so a public page sets its own; `/docs` uses `DOCS_TITLE`/`DOCS_DESCRIPTION` and `site.docs_data` (WebPage and BreadcrumbList JSON-LD); both pages carry the Organization. `/.well-known/security.txt` is generated (`SECURITY_TXT_DAYS` ahead). Guides: `GUIDES` in `app.py` (slug, title, `seo_title`, description, `updated`) and one template per slug in `templates/guides/` extending `guides/_layout.html` (breadcrumb, the "not tax advice" note, a sign up box, the other guides); `guide_page_data()` builds their JSON-LD (Article or CollectionPage, BreadcrumbList); the sitemap lists them with `updated` as lastmod, so change it with the text. The day line in their text and titles is `{{ threshold }}`/`RESIDENCE_THRESHOLD`, never typed (tests/test_guides.py checks it), and the slug `183-day-rule` stays as it is (links point to it). The 404 page is the standalone `static/404.html`, served by the error handler. The signed-in app lives under `/app`, `/plan`, `/settings`, `/admin`, `/year/...`, `/movements/...`, `/documents/...`.

## Conventions

- No em dashes or en dashes anywhere: code, UI text, markdown, commit messages.
- Releases follow semantic versioning from 1.0.0 (stable): patch bumps for fixes. Update `APP_VERSION` in `app.py`, the "Current version" line in `README.md`, and add a `CHANGELOG.md` entry; then commit and push to `master`. A release that adds a table or column, or needs a server step, also gets a line in the upgrade list of `setup_vps.md`.
- Document new settings in `config.env.example` and the README configuration table. `config.env`, `data/` and `uploads/` are git-ignored.
